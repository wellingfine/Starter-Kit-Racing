# 08 - 已知问题与改进建议

按严重程度排序。前两条建议优先处理。

## 一、资源缺失

### 1. `models/track-ramp.glb` 文件不存在 ⚠️

**现象**：`models/Library/mesh-library.tscn` 第 7 行引用了它：

```
[ext_resource type="PackedScene" uid="uid://dhc1lsb41pv6p" path="res://models/track-ramp.glb" id="7_0c7ya"]
```

但 `models/` 目录下并没有这个文件。

**影响**：**运行时不受影响**。`mesh-library.tres` 里已经烘焙好了网格数据，GridMap 正常工作，坡道也能用。

**风险**：只有在编辑器里**重新从场景生成 MeshLibrary** 时才会失败。

**处理建议**：
- 若不需要重新生成，可以忽略；
- 若需要，`mesh-library.tscn` 中删除该 ext_resource 与对应的 `track-ramp` 节点，或找回原始 `.glb` 放回 `models/`。

## 二、逻辑缺陷

### 2. 腾空时仍在施加动力

```148:158:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
	protected virtual void HandleInput(float delta)
	{

		if (_raycast.IsColliding())
		{
			_input.X = Input.GetAxis("left", "right");
			_input.Z = Input.GetAxis("back", "forward");
		}

		_sphere.AngularVelocity += _vehicleModel.GlobalTransform.Basis.X * (LinearSpeed * 100) * delta;
	}
```

`_sphere.AngularVelocity +=` 这行在着地判断**之外**，而 `_input` 在空中保留着上一帧的值，所以车辆离地后仍在持续「踩油门」。

**修复建议**：把施力也放进 `if (_raycast.IsColliding())` 块内，或按着地状态缩放系数。

### 3. `PrevPosition` 未初始化，首帧撞击音量异常

`protected Vector3 PrevPosition` 默认为 `Vector3.Zero`，首帧会算出 `LinearVelocity = (position - 0) / step`，得到一个几十倍大的异常值。虽然只影响撞击音效，但可能触发一次满音量撞击声。

**修复建议**：在 `_Ready()` 末尾初始化：

```csharp
public override void _Ready()
{
    base._Ready();
    PrevPosition = _vehicleModel.Position;
}
```

### 4. 落地帧强制清空油门

```98:102:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
			if (!Colliding)
			{
				if (VehicleBody != null) VehicleBody.Position = new Vector3(0, 0.1f, 0); // 落地回弹
				_input.Z = 0;
			}
```

刚落地时把 `_input.Z` 清零一帧。在连续颠簸路面上会造成可感知的顿挫。

**修复建议**：改为衰减而非清零，例如 `_input.Z *= 0.5f`。

### 5. 启动瞬间音频爆音

`ScreechSound` 和 `EngineSound` 都是 `autoplay = true`，而 `AudioStreamPlayer3D` 初始 `volume_db = 0`（即满音量），脚本要到下一帧才把它 `lerp` 下来。启动瞬间会有极短的全音量爆音。

**修复建议**：在场景里把两者的初始 `volume_db` 设成 `-80`，让脚本平滑推上来。

### 6. `View.cs` 的 `Target` 未判空

```24:24:d:/gproject/Starter-Kit-Racing/scripts/View.cs
		Position = Position.Lerp(Target.GetVehiclePosition(), (float)delta * 4);
```

`Target` 是 `[Export]` 属性，未赋值时 `_PhysicsProcess` 直接崩溃。换载具后容易忘记重新指定（[快速开始](02-快速开始.md) 的操作步骤里提醒了这一步）。

**修复建议**：加判空，或在 `_Ready()` 里校验并用 `GD.PushError` 提示。

### 7. `bounce` 输入动作是死配置

`project.godot` 定义了 `bounce`（空格键）动作，但全项目没有任何脚本使用它。

**说明**：`Vehicle.cs` 里 `// 落地回弹` 注释指的是**落地弹跳时的车身位移**，与该输入动作无关，容易误以为有关联。

**处理建议**：删除该动作，或实现成跳跃/加速功能。

## 三、代码风格

### 8. 时间步获取方式不一致

`EffectTrails()` 用 `GetPhysicsProcessDeltaTime()`，而其它方法用传入的 `delta`。结果等价，但可读性差：

```228:228:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		_screechSound.VolumeDb = Mathf.Lerp(_screechSound.VolumeDb, targetVolume, 10.0f * (float)GetPhysicsProcessDeltaTime());
```

### 9. `EffectTrails()` 未接收 `delta` 参数

与其它三个 `Effect*` 签名不一致（`EffectTrails()` vs `EffectEngine(float delta)`），不利于子类重写时统一处理。

## 四、缺失的功能

### 10. 没有任何比赛逻辑

这是模板的**预期范围**，但如果要做成完整游戏，需要自行补充：

- 圈数统计与检查点（防止抄近道）
- 计时 / 最佳成绩
- 名次与排行榜
- AI 对手
- 开始倒计时、暂停、重开
- 小地图 / HUD

### 11. 碰撞层设计较为随意

物理球 `collision_layer = 8`，`collision_mask` 用默认值 1；地面与 GridMap 都在 layer 1，所以能正常碰撞。但新增障碍物（墙、道具）时需要注意层设置，否则会出现「穿墙」或「无效碰撞」。

---

## 五、性能相关

### 12. 渲染配置偏重

MSAA 2×、SSAO quality 3 且 `half_size=false`（全分辨率）、SSIL、Glow 全开。桌面端无压力，但移动端/低端机需要降配：

1. `environment/ssao/half_size` → `true`（收益最大）
2. `environment/ssao/quality` → `1`
3. `anti_aliasing/quality/msaa_3d` → `0`，改用 FXAA
4. 关闭 `ssil_enabled`

详见 [项目设置](07-项目设置.md)。

### 13. `View.cs` 每帧读取 `Target.LinearSpeed`

跨节点访问属性成本很低，但如果后续要支持多辆 AI 车，建议把相机逻辑改为事件驱动或缓存引用。
