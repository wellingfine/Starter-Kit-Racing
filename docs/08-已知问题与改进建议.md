# 08 - 已知问题与改进建议

按严重程度排序。前两条建议优先处理。

## 一、资源缺失

### 1. `models/track-ramp.glb` 文件不存在 ⚠️

**现象**：`models/Library/mesh-library.tscn` 第 7 行引用了它：

```
[ext_resource type="PackedScene" uid="uid://dhc1lsb41pv6p" path="res://models/track-ramp.glb" id="7_0c7ya"]
```

但 `models/` 目录下并没有这个文件。

**影响**：**运行时不受影响**。`mesh-library.tres` 里已经烘焙好了网格数据，GridMap 正常工作，坡道也能用。

**风险**：只有在编辑器里**重新从场景生成 MeshLibrary** 时才会失败。

**处理建议**：
- 若不需要重新生成，可以忽略；
- 若需要，`mesh-library.tscn` 中删除该 ext_resource 与对应的 `track-ramp` 节点，或找回原始 `.glb` 放回 `models/`。

## 二、逻辑缺陷

### 2. 腾空时仍在施加动力

```113:119:d:/gproject/Starter-Kit-Racing/scripts/vehicle.gd
func handle_input(delta):

	if raycast.is_colliding():
		input.x = Input.get_axis("left", "right")
		input.z = Input.get_axis("back", "forward")

	sphere.angular_velocity += vehicle_model.get_global_transform().basis.x * (linear_speed * 100) * delta
```

`angular_velocity +=` 这行在着地判断**之外**，而 `input` 在空中保留着上一帧的值，所以车辆离地后仍在持续「踩油门」。

**修复建议**：把施力也放进 `if raycast.is_colliding():` 块内，或按着地状态缩放系数。

### 3. `prev_position` 未初始化，首帧撞击音量异常

`var prev_position: Vector3` 默认为 `(0,0,0)`，首帧会算出 `linear_velocity = (position - 0) / delta`，得到一个几十倍大的异常值。虽然只影响撞击音效，但可能触发一次满音量撞击声。

**修复建议**：在 `_ready()` 中初始化：

```gdscript
func _ready():
    prev_position = vehicle_model.position
```

### 4. 落地帧强制清空油门

```67:70:d:/gproject/Starter-Kit-Racing/scripts/vehicle.gd
		if !colliding:
			if vehicle_body != null: vehicle_body.position = Vector3(0, 0.1, 0) # Bounce
			input.z = 0
```

刚落地时把 `input.z` 清零一帧。在连续颠簸路面上会造成可感知的顿挫。

**修复建议**：改为衰减而非清零，例如 `input.z *= 0.5`。

### 5. 启动瞬间音频爆音

`ScreechSound` 和 `EngineSound` 都是 `autoplay = true`，而 `AudioStreamPlayer3D` 初始 `volume_db = 0`（即满音量），脚本要到下一帧才把它 `lerp` 下来。启动瞬间会有极短的全音量爆音。

**修复建议**：在场景里把两者的初始 `volume_db` 设成 `-80`，让脚本平滑推上来。

### 6. `view.gd` 的 `target` 未判空

```14:14:d:/gproject/Starter-Kit-Racing/scripts/view.gd
	self.position = self.position.lerp(target.get_vehicle_position(), delta * 4)
```

`target` 是 `@export` 变量，未赋值时 `_physics_process` 直接崩溃。换载具后容易忘记重新指定（README 第 4 条操作就是提醒这一步）。

**修复建议**：加判空，或加 `@export` 的 `tool` 提示。

### 7. 摩托车 `fork` 节点未判空

```36:38:d:/gproject/Starter-Kit-Racing/scripts/vehicle-motorcycle.gd
	if wheel_front != null:
		fork.rotation.y = lerp_angle(fork.rotation.y, -input.x / 1.5, delta * 5)
		wheel_front.rotation.y = lerp_angle(wheel_front.rotation.y, -input.x / 1.5, delta * 10)
```

`fork` 被直接使用，只在 `wheel_front != null` 的保护下。两者同属一个模型，实际风险低，但与基类「全部判空」的风格不一致。

### 8. `bounce` 输入动作是死配置

`project.godot` 定义了 `bounce`（空格键）动作，但 grep 全项目没有任何脚本使用它。

**说明**：`vehicle.gd:69` 注释里的 `# Bounce` 指的是**落地弹跳时车身位移**，与该输入动作无关，容易误以为有关联。

**处理建议**：删除该动作，或实现成跳跃/加速功能。

## 三、代码风格

### 9. 时间步获取方式不一致

`effect_trails()` 用 `get_physics_process_delta_time()`，而其它方法用传入的 `delta`。结果等价，但可读性差：

```176:176:d:/gproject/Starter-Kit-Racing/scripts/vehicle.gd
	screech_sound.volume_db = lerp(screech_sound.volume_db, target_volume, 10.0 * get_physics_process_delta_time())
```

### 10. `effect_trails()` 未接收 `delta` 参数

与其它三个 `effect_*` 签名不一致（`effect_trails()` vs `effect_engine(delta)`），不利于子类重写时统一处理。

## 四、缺失的功能

### 11. 没有任何比赛逻辑

这是模板的**预期范围**，但如果要做成完整游戏，需要自行补充：

- 圈数统计与检查点（防止抄近道）
- 计时 / 最佳成绩
- 名次与排行榜
- AI 对手
- 开始倒计时、暂停、重开
- 小地图 / HUD

### 12. 碰撞层设计较为随意

物理球 `collision_layer = 8`，`collision_mask` 用默认值 1；地面与 GridMap 都在 layer 1，所以能正常碰撞。但新增障碍物（墙、道具）时需要注意层设置，否则会出现「穿墙」或「无效碰撞」。

## 五、性能相关

### 13. 渲染配置偏重

MSAA 2×、SSAO quality 3 且 `half_size=false`（全分辨率）、SSIL、Glow 全开。桌面端无压力，但移动端/低端机需要降配：

1. `environment/ssao/half_size` → `true`（收益最大）
2. `environment/ssao/quality` → `1`
3. `anti_aliasing/quality/msaa_3d` → `0`，改用 FXAA
4. 关闭 `ssil_enabled`

详见 [项目设置](07-项目设置.md)。

### 14. `view.gd` 每帧读取 `target.linear_speed`

跨节点访问属性成本很低，但如果后续要支持多辆 AI 车，建议把相机逻辑改为事件驱动或缓存引用。
