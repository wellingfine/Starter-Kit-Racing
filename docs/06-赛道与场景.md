# 06 - 赛道与场景

## 主场景 `scenes/main.tscn`

```
Main (Node3D)
├── Environment    WorldEnvironment
├── Plane          StaticBody3D + CollisionShape3D
├── View           Node3D（脚本 view.gd）
│   └── Camera     Camera3D
├── Sun            DirectionalLight3D
├── GridMap        GridMap
├── vehicle-truck-green / -purple / -red    纯装饰
└── Vehicle        scenes/vehicle.tscn 的实例
```

### `Plane` —— 兜底地面

一个 60×60 的 `BoxShape3D`，`friction = 0.0`、`bounce = 0.1`。它的作用是**防止车掉出赛道后无限下坠**，而不是提供摩擦力。因为几乎无摩擦，车一旦开到这块平地上会明显「打滑」，这在体验上其实是个提示：你出界了。

### `Sun` —— 光照

| 属性 | 值 |
| --- | --- |
| `shadow_enabled` | true |
| `shadow_opacity` | 0.75（半透明阴影，风格化处理） |
| `shadow_normal_bias` | 1.0（消除自阴影条纹） |
| `directional_shadow_max_distance` | 30.0 |
| `directional_shadow_blend_splits` | true（消除分段接缝） |
| `sky_mode` | 1（仅天空，避免影响场景明暗） |

### `View` —— 相机

初始位置 `(3.5, 0, 5)`，相机 FOV 40°、`far = 60`。跟随逻辑见 [脚本参考](05-脚本参考.md)。

## 赛道系统：GridMap

```51:55:d:/gproject/Starter-Kit-Racing/scenes/main.tscn
[node name="GridMap" type="GridMap" parent="." unique_id=746223562]
transform = Transform3D(0.75, 0, 0, 0, 0.75, 0, 0, 0, 0.75, 0, -0.5, 0)
mesh_library = ExtResource("8_eg7gk")
physics_material = SubResource("PhysicsMaterial_tipki")
cell_size = Vector3(9.99, 1, 9.99)
```

三个值得注意的配置：

1. **`cell_size = 9.99` 而不是 10**。地块模型本身尺寸是 10，这里故意取略小的值，让相邻格子有极小的重叠，避免出现浮点缝隙（Z-fighting 或射线漏检）。这是一个很实用的小技巧。
2. **整体缩放 0.75**。地块按 10 单位建模，缩放后实际格距 7.5，配合车辆尺寸得到合适的比例。
3. **Y 方向 -0.5 偏移**，让地块顶面大致对齐 y=0 平面。

### MeshLibrary

`models/Library/mesh-library.tres` 是 GridMap 实际使用的资源。它的生成方式是：在 `mesh-library.tscn` 里摆好所有地块 → 用「场景 → 转换」功能导出为 MeshLibrary。

地块清单（来自 `.tres` 的 `item/*/name`）：

| 类型 | 模型 |
| --- | --- |
| 赛道 | `track-straight`（直线）、`track-corner`（弯道）、`track-ramp`（坡道）、`track-bump`（颠簸）、`track-finish`（终点线）、`track-tents`（帐篷区） |
| 装饰 | `decoration-empty`（空地）、`decoration-forest`（森林）、`decoration-tents`（帐篷） |

### 碰撞的处理方式

赛道碰撞不是用视觉网格直接做碰撞，而是用单独的 `collision-track-straight.fbx` / `collision-track-corner.fbx` 烘焙成 `ConcavePolygonShape3D` 存进 MeshLibrary。这样碰撞体是简化过的凸分解网格，性能远好于直接用高面数视觉网格。

> 注意：`project.godot` 里设置了 `filesystem/import/fbx/enabled=false`，即**禁用 FBX 运行时导入**。这意味着碰撞网格必须已经烘焙进 `.tres`，不能再从 `.fbx` 现场导入。

## 世界环境 `main-environment.tres`

| 设置 | 值 | 说明 |
| --- | --- | --- |
| `background_mode` | 1（Sky） | 程序化天空 |
| `ambient_light_source` | 2（Sky） | 环境光取自天空 |
| `tonemap_mode` | 2（Filmic / ACES） | 电影级色调映射 |
| `tonemap_exposure` | 0.9 | 略降曝光 |
| `ssao_enabled` | true，`intensity 4.0` / `power 2.5` | 屏幕空间环境光遮蔽 |
| `ssil_enabled` | true，`radius 3.0` / `intensity 1.25` | 屏幕空间间接光 |
| `glow_enabled` | true，`strength 1.25` | 辉光 |

整体是明亮、低对比的卡通风渲染，和 Kenney 的美术风格一致。

## 载具场景对比

`vehicle.tscn` 与 `vehicle-motorcycle.tscn` 结构高度对称，差异只在：

| 项目 | 卡车 | 摩托车 |
| --- | --- | --- |
| 脚本 | `vehicle.gd` | `vehicle-motorcycle.gd` |
| 引擎音 | `engine.ogg` | `engine-motorcycle.ogg` |
| 模型路径 | `Container/Model` | `Container/Model`（内部多一层 `motorcycle`） |
| 烟雾发射器 | 左右各一个（对应四个轮子） | **只有一个** `TrailLeft`，位置居中 `(0, 0.05, -0.2)` |
| 粒子缩放曲线 | 峰值 1.0 | 峰值 1.5（`_limits` 上限放宽到 1.5） |

物理球 `Sphere` 的配置两者完全一致。

## 轮胎烟雾粒子

两个载具共用同一份 `ParticleProcessMaterial` 配置要点：

- `gravity = Vector3(0,0,0)`：烟雾不受重力，保持贴地扩散；
- `damping = 1.0`：粒子快速减速；
- `scale_curve` + `alpha_curve`：从 0 涨到峰值再淡出；
- `angle_min/max = ±90°`：随机旋转，避免看出来是同一张图；
- 材质用 `billboard_mode = 3`（固定 Y 轴 billboard）+ `proximity_fade_enabled`（近处淡出，避免穿插硬边）。

## 三辆装饰卡车

`vehicle-truck-green/purple/red` 直接以 `.glb` 实例挂在 `Main` 下，**没有脚本、没有碰撞体**，纯装饰。它们的作用是展示「同一套模型可以有多种配色」，以及让场景不空。
