# 04 - 车辆系统

这是整个项目最核心、最值得学习的部分。

> 本文示例均取自 `scripts/Vehicle.cs` 与 `scripts/VehicleMotorcycle.cs`。

## 一、为什么不用 `VehicleBody3D`

Godot 内置了 `VehicleBody3D` + `VehicleWheel3D`，但它参数多、调参难，高速下容易不稳定（官方故障排查文档也提到了这一点）。本项目**完全没用它**，而是自创了一套「球体代理」方案。

## 二、球体代理物理

### 节点结构

```
Vehicle (Node3D)              ← scripts/Vehicle.cs
├── Ground    RayCast3D       ← 从球位置向下 0.7 探测地面法线
├── Container Node3D          ← 纯视觉层，跟随物理球
│   ├── Model                 车模型
│   ├── TrailLeft / TrailRight
│   └── ScreechSound / EngineSound / ImpactSound
└── Sphere    RigidBody3D     ← 唯一真正的物理体
```

`Sphere` 的关键配置（在 `scenes/vehicle.tscn` 中）：

| 属性 | 值 | 作用 |
| --- | --- | --- |
| `mass` | 1000.0 | 大质量带来沉稳感 |
| `gravity_scale` | 1.5 | 比常规重力更重，减少腾空 |
| `angular_damp` | 4.0（`mode=1` 替换模式） | 抑制球体乱转 |
| `linear_damp` | 0.1 | 轻微空气阻力 |
| `continuous_cd` | true | 高速防穿透 |
| `physics_material_override` | friction 5.0 / rough true | **关键**：靠高摩擦把自转转成位移 |
| `collision_layer` | 8 | 只与 layer 1（地面/GridMap）碰撞 |

### 驱动原理：给球加「角速度」而不是加「力」

这是整个方案最巧妙的地方。传统做法是 `ApplyForce` / `ApplyCentralForce`，而这里是让球**自转**，靠球与地面的摩擦力把旋转转换成平移：

```157:157:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		_sphere.AngularVelocity += _vehicleModel.GlobalTransform.Basis.X * (LinearSpeed * 100) * delta;
```

注意旋转轴取的是 **`_vehicleModel` 的 `Basis.X`**（视觉模型的右向量），而不是球体自身的轴。这一行代码同时决定了两件事：

- 车往哪开 → 由模型朝向决定；
- 转向为什么是瞬时的 → 因为模型一转，驱动轴立刻跟着转。

### 转向：纯视觉旋转

```89:92:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		float targetAngular = -_input.X * steeringGrip * 4 * direction;
		AngularSpeed = Mathf.Lerp(AngularSpeed, targetAngular, step * 4);

		_vehicleModel.RotateY(AngularSpeed * step);
```

转向**完全不经过物理系统**，只是旋转视觉模型。配合上面那行 `Basis.X` 取轴，就得到了街机式的即时转向手感：

- 优点：响应快、手感干脆、无需调侧向摩擦参数；
- 代价：**没有真实的漂移与抓地力物理**，车不会侧滑。

转向幅度还随速度变化，低速时方向更「钝」，避免原地打转：

```87:87:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		float steeringGrip = Mathf.Clamp(Mathf.Abs(LinearSpeed), 0.2f, 1.0f);
```

### 贴地对齐

`Ground`（RayCast3D）从球心向下 0.7 探测，取地面法线后重建模型的基向量，并插值 20% 平滑，避免在坡道/接缝处抖动：

```108:112:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
			if (Normal.Dot(_vehicleModel.GlobalBasis.Y) > 0.5f)
			{
				Transform3D xform = AlignWithY(_vehicleModel.GlobalTransform, Normal);
				_vehicleModel.GlobalTransform = _vehicleModel.GlobalTransform.InterpolateWith(xform, 0.2f).Orthonormalized();
			}
```

```233:242:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
	protected static Transform3D AlignWithY(Transform3D xform, Vector3 newY)
	{
		Basis basis = xform.Basis;
		basis.Row1 = newY;
		basis.Row0 = -basis.Row2.Cross(newY);
		basis = basis.Orthonormalized();
		xform.Basis = basis;

		return xform;
	}
```

`Normal.Dot(...) > 0.5f` 这个判断是为了防止车翻过来或撞到垂直墙面时被强行「吸」到墙面上。

> C# 注意点：`Basis` 是**结构体**，`xform.Basis.Row1 = newY` 这种写法在 C# 里不成立（不能修改属性返回的临时副本），必须先取出局部变量、改完再整体赋值回去。`Row0/Row1/Row2` 即基向量的 X / Y / Z 三列。

### 速度模型：一个虚拟标量

`LinearSpeed` **不是**物理速度，而是一个用 `Mathf.Lerp` 逼近输入的抽象值。这样可以把加速、刹车、倒车的手感拆开精细调节：

```119:124:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		if (targetSpeed < 0 && LinearSpeed > 0.01f)
			LinearSpeed = Mathf.Lerp(LinearSpeed, 0.0f, step * 8);
		else if (targetSpeed < 0)
			LinearSpeed = Mathf.Lerp(LinearSpeed, targetSpeed / 2, step * 2);
		else
			LinearSpeed = Mathf.Lerp(LinearSpeed, targetSpeed, step * 6);
```

三个分支分别对应：**刹车**（前进中按 S，快速归零）、**倒车**（速度归零后以半速倒退）、**加速**。

另外还有一个 `Acceleration`，它混入了球的角速度，用来驱动车轮旋转和车身俯仰：

```126:126:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		Acceleration = Mathf.Lerp(Acceleration, LinearSpeed + (Mathf.Abs(_sphere.AngularVelocity.Length() * LinearSpeed) / 100), step);
```

### 视觉层跟随物理球

```130:131:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		_vehicleModel.Position = _sphere.Position - new Vector3(0, 0.65f, 0);
		_raycast.Position = _sphere.Position;
```

模型挂在球下方 0.65，射线始终跟着球走。

## 三、特效系统

`_PhysicsProcess` 末尾依次调用 4 个特效方法，它们在 C# 里是 `protected virtual`，子类用 `override` 重写：

```140:143:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		EffectEngine(step);
		EffectBody(step);
		EffectWheels(step);
		EffectTrails();
```

### 引擎音效 `EffectEngine`

同时用「速度」和「油门」两个因子驱动音量与音调，油门额外 +0.2 音调，制造换挡感：

```202:211:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		float speedFactor = Mathf.Clamp(Mathf.Abs(LinearSpeed), 0.0f, 1.0f);
		float throttleFactor = Mathf.Clamp(Mathf.Abs(_input.Z), 0.0f, 1.0f);

		float targetVolume = Mathf.Remap(speedFactor + (throttleFactor * 0.5f), 0.0f, 1.5f, -15.0f, -5.0f);
		_engineSound.VolumeDb = Mathf.Lerp(_engineSound.VolumeDb, targetVolume, delta * 5.0f);

		float targetPitch = Mathf.Remap(speedFactor, 0.0f, 1.0f, 0.5f, 3.0f);
		if (throttleFactor > 0.1f) targetPitch += 0.2f;

		_engineSound.PitchScale = Mathf.Lerp(_engineSound.PitchScale, targetPitch, delta * 2.0f);
```

### 车身姿态 `EffectBody`

- `Rotation.X`：加速抬头 / 刹车点头，取 `-(LinearSpeed - Acceleration) / 6`；
- `Rotation.Z`：转向侧倾 `CalculatedLean`；
- `Position`：向 `new Vector3(0, 0.2f, 0)` 缓慢回弹（配合落地时的弹跳）。

### 车轮 `EffectWheels`

四个轮子绕 X 轴自转（速度取 `Acceleration`），两个前轮额外绕 Y 轴转向。

### 烟雾与打滑声 `EffectTrails`

漂移强度是一个综合指标，超过 0.25 才触发：

```218:228:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
		float driftIntensity = Mathf.Abs(LinearSpeed - Acceleration) + (Mathf.Abs(CalculatedLean) * 2.0f);
		bool shouldEmit = driftIntensity > 0.25f;

		if (TrailLeft != null) TrailLeft.Emitting = shouldEmit;
		if (TrailRight != null) TrailRight.Emitting = shouldEmit;

		float targetVolume = -80.0f;
		if (shouldEmit) targetVolume = Mathf.Remap(Mathf.Clamp(driftIntensity, 0.25f, 2.0f), 0.25f, 2.0f, -10.0f, 0.0f);

		_screechSound.PitchScale = Mathf.Lerp(_screechSound.PitchScale, Mathf.Clamp(Mathf.Abs(LinearSpeed), 1.0f, 3.0f), 0.1f);
		_screechSound.VolumeDb = Mathf.Lerp(_screechSound.VolumeDb, targetVolume, 10.0f * (float)GetPhysicsProcessDeltaTime());
```

`Mathf.Abs(LinearSpeed - Acceleration)` 本质上是「轮速与实际车速的差值」——这正是现实中轮胎打滑的定义，用在街机模型里效果很好。

### 撞击音效

由 `Sphere` 的 `body_entered` 信号触发，音量按车头方向（`Basis.Z`）的速度分量计算，所以侧面擦碰不会触发巨响：

```247:256:d:/gproject/Starter-Kit-Racing/scripts/Vehicle.cs
	public void _on_sphere_body_entered(Node body)
	{
		if (VehicleBody == null) return;

		if (!_impactSound.Playing)
		{
			float impactVelocity = Mathf.Abs(LinearVelocity.Dot(VehicleBody.GlobalBasis.Z));
			_impactSound.VolumeDb = Mathf.Clamp(Mathf.Remap(impactVelocity, 0.0f, 6.0f, -20.0f, 0.0f), -20.0f, 0.0f);
			_impactSound.Play();
		}
	}
```

回调名仍写作 snake_case 的 `_on_sphere_body_entered`，因为 `scenes/vehicle.tscn` 里的信号连接记录的就是这个名字，改成 PascalCase 会连不上。

## 四、如何扩展成摩托车

`VehicleMotorcycle.cs` 继承自 `Vehicle`，只重写了两个方法：

```34:45:d:/gproject/Starter-Kit-Racing/scripts/VehicleMotorcycle.cs
	protected override void EffectBody(float delta)
	{
		float targetLean = -_input.X / 5 * LinearSpeed;
		CalculatedLean = Mathf.LerpAngle(CalculatedLean, targetLean, delta * 5);

		if (_motorcycle == null || VehicleBody == null) return;

		_motorcycle.Rotation = new Vector3(
			_motorcycle.Rotation.X,
			_motorcycle.Rotation.Y,
			Mathf.LerpAngle(_motorcycle.Rotation.Z, _input.X * LinearSpeed, delta * 3)
		);
```

关键差异：

- 汽车是「车身侧倾」，摩托车是**整车压弯**（`_motorcycle.Rotation.Z`），这是两者观感上最大的区别；
- 车轮只有前后两个，且前轮转向要连带动 `fork`（前叉）一起转；
- `_Ready()` 中重新指定了 `VehicleBody` 的路径，因为摩托车模型层级更深：

```18:30:d:/gproject/Starter-Kit-Racing/scripts/VehicleMotorcycle.cs
	public override void _Ready()
	{
		base._Ready(); // 先让基类取好 Sphere / Container / 音效等引用

		_motorcycle = GetNodeOrNull<Node3D>("Container/Model/motorcycle");
		_fork = GetNodeOrNull<Node3D>("Container/Model/motorcycle/body/fork");

		_wheelFront = GetNodeOrNull<Node3D>("Container/Model/motorcycle/wheel-front");
		_wheelBack = GetNodeOrNull<Node3D>("Container/Model/motorcycle/wheel-back");

		// 摩托车模型层级更深，车身节点要重新指定路径
		VehicleBody = GetNode<Node3D>("Container/Model/motorcycle/body");
	}
```

> ⚠️ 子类重写 `_Ready()` 时**必须调用 `base._Ready()`**，否则基类的 `Sphere`、`Container`、音效等引用都不会初始化——节点引用是在 `_Ready()` 里用 `GetNode<T>` 取的，这是新增载具时最容易踩的坑。

## 五、这套方案的取舍

| 优点 | 局限 |
| --- | --- |
| 代码极少（核心逻辑约 260 行） | 没有真实漂移物理 |
| 参数直观、好调 | 空中仍会施加动力（见 [已知问题](08-已知问题与改进建议.md)） |
| 高速稳定，不会像 `VehicleBody3D` 那样抖动 | 无法模拟不同轮胎/路面抓地力差异 |
| 换模型零成本 | 碰撞体始终是球，与车外形无关 |

如果你的目标是**街机/卡丁车风格**（马里奥赛车那种），这套方案非常合适；如果需要**拟真赛车**（抓地力、重量转移、悬挂行程），则应改用 `VehicleBody3D` 或自己实现射线悬挂。

相机持有的是**编译期强类型** `Vehicle`，写错类型在编译阶段就会报错，不用等到运行才发现。
